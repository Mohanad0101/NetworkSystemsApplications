1. Id показывает uid=2003(user_3), gid=2003(user_3), groups=2003(user_3),1002(students). Как это прочитать?

UID идентифицирует пользователя, GID — группу. В дополнительных группах можно состоять независимо от основной группы.

2. Почему обычному пользователю обычно разрешено читать /etc/passwd, но не /etc/shadow?

В passwd находятся логин, UID, GID, домашний каталог и оболочка. При shadow-паролях секретные сведения отделены от этих общих данных.

3. Нужно добавить user_3 в students, сохранив прежние дополнительные группы. Какая форма подходит?

-a добавляет группы к существующему списку. Без -a параметр -G заменяет список дополнительных групп.

4. Администратор выполняет sudo -u user_3 cat /labs/list. От чьего имени читается файл?

-u выбирает целевого пользователя. Такая проверка моделирует его доступ; обычное sudo cat без -u обычно проверяло бы доступ root.

6. У обычного файла root:workers права 640. User_1 состоит в workers, не является владельцем, путь доступен. Что разрешают эти биты?

Групповая тройка 4 означает r--. Первая цифра относится к владельцу, а не ко всем пользователям.

11. Новый обычный файл запрашивает режим 0666, umask равна 0027. При отсутствии default ACL какие права получатся?

Маска убирает выбранные биты: группе запрещена запись, остальным — весь доступ. Это побитовая операция, а не десятичное или обычное восьмеричное вычитание.

12. Почему в опыте записи используется sudo -u user_1 bash -c 'echo try >> /labs/list', а не только sudo -u user_1 echo try >> /labs/list?

Перенаправление выполняет оболочка, которая его разбирает. Bash под -u проверяет запись в контексте целевого пользователя.
